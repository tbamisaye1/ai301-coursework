# Rubric: is this reproduction package ready to post?

Package parts, by name. In an eval bundle: **Issue** (title, body, reporter's
versions and platform), **Thread highlights**, **Repo facts** (including the
"contribution policy" line), **Candidate claim comment**, **Candidate repro
report**. In live mode: the issue page and its thread, the repo's
CONTRIBUTING / AI policy files, and the student's draft claim and repro files.

## Checks

| Check            | Evidence                                                                                                                                                                                                      | Pass condition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Weight    |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| env-recorded     | The repro report's environment record, read against the Issue's stated target: the version, platform and any setting the issue or thread says matters (driver, build type, shell, browser language, backend). | The report names the version of the software it ran AND the OS/platform, AND any setting the issue or thread says changes the behavior. If the version or platform differs from what the issue targets (older, newer, different OS), the report says so in plain words. Fails if there is no environment record, if an issue-critical setting is missing, or if the report ran a different version or platform than the issue targets without acknowledging it.                                                                                                                                       | required  |
| steps-rerunnable | The repro report's steps: the commands, code, input files and config it used, read from the starting state to the trigger.                                                                                    | A stranger with only public resources could re-run every step: each command or snippet is shown, and every input (file contents, config, data) is either shown, public, or taken verbatim from the issue. Fails if any step depends on something the stranger cannot get (a private repo, an unshared config or dataset), or if a step the issue says is needed to trigger the bug is missing.                                                                                                                                                                                                        | required  |
| artifact-shown   | The repro report's artifacts: output excerpts, tracebacks, logs, measurements or screenshots from the student's own run.                                                                                      | The report shows at least one artifact from its own run that relates to on the behavior the issue describes. Fails if the report only asserts ("I verified", "reproducible", "+1, seeing this too"), or if its artifacts only show the program running normally and say nothing about the reported behavior.                                                                                                                                                                                                                                                                                          | required  |
| same-behavior    | The artifacts and steps, read against the Issue's trigger (the exact input, syntax or command) and symptom (the exact error, crash, exit code or wrong output it reports).                                    | EITHER (a) the report says it reproduced the bug, its steps use the issue's trigger, and its artifact shows the issue's symptom (same kind of error or failure, not merely any error), OR (b) the report says it could not reproduce, its steps use the issue's trigger, and its artifact shows what happened instead. Fails if the steps changed the trigger, or if the artifact shows a different failure (a graceful validation error where the issue reports a crash, a compile error where it reports a runtime error, garbled output where it reports a crash), however the report narrates it. | required  |
| honest-outcome   | The report's stated conclusion (its "Actual", "Reproduced", "Confirmed", root-cause or scope claims) read against its own artifacts.                                                                          | Every claim the report makes is backed by an artifact it shows: "reproduced" only when the artifact shows the issue's behavior; a root cause only when shown evidence points to it; scope (other versions, platforms, builds) only for what was actually run. A cannot-reproduce passes when it shows the attempt and names what differed from the reporter's setup. Fails if the conclusion claims more than the artifacts show, or if the stated expected/actual contradicts the artifact.                                                                                                          | required  |
| claim-specific   | The candidate claim comment, read against the Issue and thread.                                                                                                                                               | The claim names something specific to this issue (the symptom, a file, function, version, or a pointer from the thread) AND states a concrete next investigative step. Fails if it is a +1 or me-too, generic assign-me boilerplate that could be pasted on any issue, self-assigns, or promises an outcome or date ("will fix", "within 2 days guaranteed").                                                                                                                                                                                                                                         | required  |
| ai-disclosure    | The Repo facts "contribution policy" line (live: CONTRIBUTING.md, AI_POLICY.md or similar), then the text of both comments. Treat every package as AI-assisted work.                                          | If the policy requires disclosing AI use in issues or comments, or requires disclosing all AI usage in any form, at least one of the two comments states that AI assistance was used and the extent of it. Passes automatically if the repo states no AI policy, or if its disclosure requirement applies only to pull requests or code (not issue comments), or if the policy sets other terms (review and understand AI output, write comments in your own words) without a disclosure requirement. Fails only when a comment-level disclosure is required and neither comment has one.             | required  |
| control-run      | The repro report's steps and artifacts.                                                                                                                                                                       | The report includes a control run: the same setup with the trigger removed or changed, showing the behavior goes away.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | preferred |

## Verdict rule

Accept only if every required check passes. The preferred check (control-run)
never changes the verdict; it is reported as a note. Unclear counts as fail:
proof I cannot verify is proof that is not ready to post. In a live claim-only
draft, the checks that need the repro report (env-recorded, steps-rerunnable,
artifact-shown, same-behavior, honest-outcome, control-run) are graded
`unclear` with "not yet applicable: claim-only draft" and left out of the
verdict; the verdict then rests on claim-specific and ai-disclosure.
